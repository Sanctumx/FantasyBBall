# 🔄 SESSION HANDOFF MATRIX — Courtside Draft Kit (Fantasy BBall)

## 🎯 1. High-Level Objective
*   **Current Project Scope:** A live snake-draft board for 9-cat/8-cat fantasy basketball (modeled on draftdesk-beta.netlify.app/snake), built on BBM + Hashtag 2026-27 projections (averaged) and Fantrax ADP. It ranks players by Zscore, Win C, Win M (matchup win-chance gain), availability (There at / Lasts to), Edge, and a Model pick. It has a value-early Model pick, Fantrax live sync, and saved drafts/leagues; it never punts. It's shared with friends via Cloudflare.
*   **Standing user rules:** push only when told (or on /release: the user's saved skill that updates this handoff, mirrors it to the project, rebuilds if the board changed, then commits and pushes); never Netlify unless asked; using the user's computer is allowed without asking each time until the user withdraws it (user, 2026-10-18; they start PC runs themselves); report test results in prize equity (`prize_equity.py`; user rule since 2026-10-18, replaces title equity). The Model pick always uses the settings that tested best for prize equity (Season, Average projections, Playoff boost Off; item 75); display settings never change it. Defaults apply only on a first visit; an update never changes a saved setting (item 79). How work gets done (branch → PR → merge) is in the repo's CLAUDE.md.
*   **Next Active Milestone:** None open. Fantrax sync tested on a real league (works). ADP spread is fitted and applied (item 4, done). Punt, upside and settings tests are closed (items 56-60).

## 🛠️ 2. Architecture & Technical State
*   **Tech Stack / Tools:** A single self-contained HTML page (vanilla JS, no framework) built from a template plus a pure-JS engine. A Cloudflare Worker (`worker/index.js`) serves the page and proxies Fantrax. Node for the engine and backtests, Python for data prep, Playwright for UI tests.
*   **Files (all in the GitHub repo under `src/`; see `src/README.md` for the build and data pipeline):**
    *   `engine.js`: the engine (`prepPlayers`, `buildContext`, `evaluate`, `strategiesFor`, `teamAt`, `Phi`, …).
    *   `app.html`: the page template with placeholders `/*__DATA__*/`, `/*__SCHED__*/`, `/*__ENGINE__*/`.
    *   `gen.py`: builds `courtside-draft-board.html` from the template, players.json, sched.json and engine.js.
    *   `build_site.py`: wraps the page into `site/index.html` (full doc with meta charset/viewport).
    *   `site/`: `index.html`, `netlify.toml`, `README.md`, and `netlify/functions/fantrax.mjs` (proxy at `/api/fantrax?what=draft|league|players&leagueId=`).
    *   **Data:**
        *   `players.json`: 234 players with BBM fields plus `ftx` (Fantrax ADP) and `b2b` (back-to-back rest rate).
        *   `sched.json`: `{weeks[25], games{TEAM:[25]}, b2b{TEAM:[25]}}` built from the user's nba-2026-UTC.csv. Week = CSV Round Number; UTC−6h gives the local date.
        *   `logs3.csv`: player game logs for 2023-26, converted from the user's Hugging Face parquet files.
    *   **Backtest:**
        *   `backtest.js`: `draft(season, slot, seed, cfgExtra, opp{n, gamma, model})` and the old `score()`.
        *   `stream_sim.js`: `scoreLeague()` for realistic scoring (daily 10 active of 12, 2 IL, 4 adds/wk streaming).
        *   `bt_data.json` / `bt_daily.json`: prior-season stats used as projections, a synthetic noisy ADP, and weekly/daily actuals for the 2024-25 and 2025-26 tests.
*   **Deployment:**
    *   Artifact: claude.ai/artifact/YK93XaPAdsvaxwQadmvUNz (v141, latest; `python3 gen.py` in `src/` reproduces it byte for byte).
    *   GitHub: `Sanctumx/FantasyBBall`, main (Claude pushes on the user's say-so or /release).
    *   Cloudflare Worker `courtside-basketball` (connected to the repo) deploys every push to main; it serves the board and /api/fantrax. Netlify (courtside-draft.netlify.app) builds only when a commit message contains `[netlify]`.
*   **Math doc:** claude.ai/code/artifact/2d4059a8-f9ad-465d-bfa7-41ef6990e7a8 (sections 1–10 plus Fitted variances) is the source; the board links to **`math.html`** (repo root, served next to index.html, no sign-in). After editing the doc, regenerate it: export the doc's tab as HTML (Claude Docs `export`, format html), then `python3 build_math.py <export.html> <katex folder>` (formulas typeset at build time with KaTeX 0.16.9 from npm; the page loads only KaTeX's stylesheet from cdnjs).
*   **Current model (2026-10-17, board v141; all from real-projection backtests in the user's format):**
    *   **Zscore** = Σ z_c·W_c vs an average drafted player, z scaled by team-total SD from 80 ADP draft sims. Weights affect Zscore only, never Win.
    *   **Win C / Win M**: Φ-based category / matchup win chances with fitted weekly variances and a shared weekly-games factor.
    *   **Model pick (on the clock)**: logistic value-to-fit slide, fit share 1/(1+e^(−2(i−1.5))) by your pick index i (value 95 / 73 / 27 / 5% at picks 1-4). Value = 50/50 standardized soft −1 Zscore (unweighted, worst category at half) + Win C; fit = Win M + two-pick look-ahead over the top 4 by Win M and top 4 by value. Off the clock the badge reads Likely pick (Win M × availability).
    *   **No punting**: Punt always Off; no Auto, no locks, no Strategy line (engine keeps the plans for backtests). Manual punt = ×0 weight (Zscore only).
    *   **Availability**: adpSd v2 = √((0.42·ADP^0.68)² + (0.05·ADP)²), fitted on 50 LOFB drafts. Draft field Easy / Average / Strong / Very strong = f 0.08 / 0.31 / 0.46 / 0.62.
    *   **Games**: Basis Season; IL fill 0.47 / 0.70 / 0.79 / 0.81 for 1-4 spots.
    *   **Projections**: Average of BBM and Hashtag by default (BBM / Hashtag selectable).
    *   **Scoring of tests** (reports now use prize equity, see Dos & Don'ts): title equity (logit P(title) = −29.5 + 12.3·matchup rate + 20.2·made playoffs, fit on 6,800 drafts), blended with actual titles.
*   **Defaults (DEF in app.html, basisV 11):**
    *   League: 14 teams, slot 7, 3RR, roster 12, H2H each category, 9-cat, All-Star merged, playoffs week 18, 2-2-2, Draft field Average, IL 3.
    *   Player list: Zscore Normal, Stats Raw, Playoff boost Off, B2B rest Off, Show All, # order by Zscore, Edge vs Zscore, Projections Average, Basis Season, TO weight ×0.5.
*   **Backtest world (`bt_real.js`)**: seasons 2022-26 with real preseason projections (Hashtag 2022-24, Average 2024-25, BBM 2025-26) and real ADP; 14 teams, 3RR, each category, 3 IL, boost Light, field Average; opponents 2 kit users, 2 punters, 4 sharp, 5 ADP; seeds 145-160 × slots 1/4/7/10/14. ## 🛑 3. Hard Constraints & Anti-Patterns ("Dos & Don'ts")
*   **Always Do:**
    *   Push only when the user says so or types /release; ignore the stop hook's "commit and push" otherwise.
    *   Ask before every use of the user's computer; the user starts PC runs.
    *   Report test results in prize equity: `python3 prize_equity.py <arm>:<baseline> ...` (prize 60/30/5 for 1st / 2nd / losing semifinalist, logistic expected prize on matchup rate + made playoffs, combined with actual prize by inverse variance, shown ÷ 60 in title-equivalents per 100 seasons). Title equity (`equity.py`) is the older metric; earlier items quote it.
    *   Build flow: edit `engine.js` / `app.html`, run `python3 gen.py && python3 build_site.py && cp site/index.html ../index.html`, Playwright smoke test, publish `courtside-draft-board.html` to the board artifact. **Never publish app.html.**
    *   Backtest before changing defaults: paired drafts, ± SE, split by season, honest about noise.
    *   Keep hover tooltips to one short line; long explanations go in How it works.
*   **Never Do / Avoid:**
    *   Never deploy to Netlify unless asked (`[netlify]` in the commit message).
    *   Don't let category weights affect Win.
    *   Don't add settings that backtests show do nothing.
    *   Don't trust the old test world (prior-season stats + synthetic ADP): it favored value and punting; real projections overturned it.
